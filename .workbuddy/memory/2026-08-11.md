### 修复的高危问题
1. **数据丢失级 bug(新发现,比预想更严重)**:`mutate()` 非事务分支里 `conn.commit()` 写在 `with engine.connect()` 块**外面**——连接在 with 结束时已 close 回滚,而 SQLAlchemy 2.0 对已关闭连接的 commit 静默忽略(不抛异常)。导致**所有非事务增删改"界面显示成功、实际从未写入数据库"**。修复:commit 移入 with 块内。
2. **PUT/DELETE 会话模式必挂**:`do_PUT`/`do_DELETE` 用 `parse_conn_header`(只认 X-Conn),而 `/api/connect` 无条件发 token 使前端 SESSION 恒非空 → 编辑/删除行必报"缺少连接信息"。修复:改用 `resolve_conn`。
3. **任意网页可无密码读写本机库**:CORS `*` + 回环免网关验证 + 按名直连。修复:`_send_json` 不再固定 ACAO `*`,按 Origin 白名单(回环/内网 IP/同源)回显;新增 `_host_allowed`(域名形式 Host 一律 403,防 DNS rebinding);OPTIONS 同步校验。
4. **前端 esc() 实际是恒等函数**(映射值等于键,从未转义)+ onclick JS 字符串注入点。修复:esc 改为真转义,新增 `escAttr`(JS 上下文:`\`→`\\`、`'`→`\'`、`&`→`&amp;`、`"`→`&quot;`)替换 renderConnList/renderTables/openFilter/renderGrid 中 9 处 onclick 注入点。

## 「加载库列表」IM002 的根因:SQLAlchemy 空库 DSN 模式坑(已修)

- 现象:手动连接输入账号密码后点「加载库列表」必报 IM002;但带库连接/测试正常。日志(DBM_LOG=1)确认前端请求完全正确(database="" 是唯一差异)。

- 修复:build_url 的 mssql 分支 `if not dbn: dbn = "master"`(空库默认连 master,符合 ODBC 语义,加载库列表正好需要)。
- 验证:远程 25 库、本机 Sam 1 库均可列出,带库回归正常。
- 附带:临时加了 DBM_LOG=1 环境变量控制 log_message/_body 请求日志(默认关闭),方便以后排查前端请求。
